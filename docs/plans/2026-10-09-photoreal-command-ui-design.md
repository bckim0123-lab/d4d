# SPIDER 실사형 항공우주 관제 UI 디자인

## 목표

현재 SPIDER 지휘소의 기능을 유지하면서, 위성·드론 정사영상이 중심이 되는 실사형 항공우주 관제 화면으로 재구성한다. 화면을 처음 본 사용자가 “실제 작전 관제 시스템”으로 인식하되, 지도·위험·경로·승인 상태를 즉시 구분할 수 있어야 한다.

## 디자인 결정

- 메인 전장 지도가 데스크톱 가시 영역의 60% 이상을 차지한다.
- 지도 배경은 외부 API가 없어도 표시되는 로컬 정사영상 스타일 자산을 사용한다.
- 기존 SVG 구역·태그·경로·메시지 오버레이는 유지하고 지형 위에 계층적으로 합성한다.
- 항공 전자장비의 무광 금속, 적층 유리, LCD 발광, 노이즈와 비네팅을 절제해 사용한다.
- 온라인은 냉백색·청록, EMP 오프라인은 호박·적색 계열로 물리적인 모드 전환처럼 표현한다.
- 카드 나열보다 “지도 + 우측 임무 레일 + 하단 시스템 스트립” 구조를 우선한다.
- 실제 데이터와 데모 데이터는 시각적으로 구분하며, 모터 제어 기능은 추가하지 않는다.

## 정보 구조

1. 상단 상태 바: 작전명, UTC, 링크, EMP 준비 상태, 운용자 승인 상태
2. 중앙 전장: 정사영상, 고도 음영, 좌표 격자, 재밍 열지도, 계획 경로, 통신 흐름
3. 좌측 도구 레일: 편집·계획·드릴·라이브러리 모드
4. 우측 임무 레일: 선택 객체, AI 제안, 에이전트 추적, 승인 게이트
5. 하단 시스템 스트립: 성공률, 전달률, 비행 시간, XIAO NUS, FC 안전 경고

## 상호작용과 모션

- 첫 진입 시 지도→경로→계측 순으로 450ms 이내 단계적 등장
- 계획 실행 중 경로가 진행 방향대로 그려지고 통신 메시지는 짧은 펄스로 이동
- 제안 태그와 역할 전환은 호박색 투영 링으로 나타난 뒤 안정 상태로 전환
- EMP 드릴 시작 시 채도와 청록 조명이 빠지고 호박색 독립 운용 HUD로 전환
- `prefers-reduced-motion`에서는 모든 연출을 즉시 상태 변경으로 대체

## 기술 구조

- React와 기존 상태·API 계약을 유지한다.
- `BattlefieldCanvas`에 로컬 배경 자산 계층을 추가하고 SVG 오버레이는 별도 레이어로 유지한다.
- CSS 변수로 온라인/오프라인 재질과 조명을 전환한다.
- 외부 지도 API, OpenAI API, JEV는 필수 런타임 의존성으로 추가하지 않는다.
- 실사 배경 자산은 라이선스 문제가 없는 생성형 또는 자체 제작 이미지로 저장한다.

## 하네스와 검증 계약

- 작성자: Grok 4.7이 프론트 UI를 구현한다.
- 평가자: 주 에이전트가 빌드·린트·브라우저 시각 검증을 수행한다.
- 산출물: `web/src/`, `web/public/`, 필요 시 UI 전용 테스트
- 완료 기준:
  - `npm run build` 성공
  - npm high 취약점 0
  - 기존 Python 141개 테스트 유지
  - 1440×900에서 지도 중심 정보 구조 확인
  - 860px 이하 반응형과 reduced-motion 유지
  - 계획 생성·승인·EMP 드릴·BLE 패널 기능 회귀 없음
