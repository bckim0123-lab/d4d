# SPIDER 지휘소 제품 요구사항

## 1. 제품 정의

**EMP 이후의 일을 EMP 이전에 끝낸다.**

SPIDER 지휘소는 통신과 클라우드가 살아 있는 동안 AI 에이전트와 결정론적 플래너가 전장을 분석하고, 검증된 드론 임무와 종이 AprilTag 플랜 카드를 미리 생성하는 도구다. EMP 발생 뒤에는 API나 LLM에 의존하지 않는다. 차폐함의 드론은 플랜 카드를 읽고 사전 승인된 경로와 규칙만 실행한다.

LLM은 자연어를 구조화하고 결과를 설명한다. 경로, 성공률, 전달률, 안전 판정은 기존 `d4d_planner`가 계산한다.

## 2. 목표와 비목표

### 목표

1. 운용자가 코드를 몰라도 지도와 자연어로 전장을 정의한다.
2. 에이전트의 분석·수정·검증 과정을 실시간으로 확인한다.
3. 사람 승인 전에는 어떤 임무도 `사용 가능` 상태가 되지 않는다.
4. 승인된 임무를 `mission.json`, `mission_data.h`, 리포트와 플랜 카드로 묶는다.
5. EMP 발생부터 귀환까지를 2분 이내 데모로 이해시킨다.
6. LLM 키가 없어도 결정론적 폴백으로 전체 데모가 동작한다.

### 비목표

- 실제 EMP 방호 성능 인증
- 원격 아밍 또는 모터 구동
- 비행 중 클라우드 의존
- LLM이 임의로 수치나 안전 판정을 생성하는 것

## 3. 사용자

- **운용자**: 전장을 편집하고 분석을 실행하며 설치 목록과 임무를 승인한다.
- **기술 담당자**: JSON, 추적 기록, C 헤더와 보드 상태를 확인한다.
- **심사위원/관람자**: 온라인 준비와 오프라인 실행의 차이를 짧은 데모로 이해한다.

## 4. 핵심 사용자 흐름

1. `demo_spider` 또는 새 시나리오를 연다.
2. 지도에서 구역·태그·노드·목표를 편집하거나 자연어로 변경을 요청한다.
3. 변경 diff를 확인한 뒤 적용한다.
4. 에이전트를 실행해 `analyze → plan → suggest → verify` 스트림을 본다.
5. 성공률·전달률·설치 항목·안전 경고를 확인한다.
6. 운용자가 명시적으로 승인한다.
7. 플랜 카드와 둥지 패키지를 다운로드한다.
8. EMP 드릴에서 카나리아 정지, 둥지 개방, 카드 판독, 비행, 교신, 귀환을 재생한다.

## 5. 화면 요구사항

### 5.1 전장 편집기

- 중앙 SVG 지도, 좌측 도구, 우측 속성 패널의 지휘소 레이아웃
- 장애물·금지·재밍·광류저하 구역 표시
- 태그, BLE 노드, 광학 메일박스, 출발점, 목표, 메시지 표시
- 클릭으로 선택, 빈 지도 클릭으로 태그 추가, 선택 항목 삭제·속성 변경
- JSON 편집기와 지도 양방향 동기화
- `ScenarioError`를 사용자에게 그대로 표시
- 자연어 요청 결과를 변경 요약과 JSON diff로 먼저 표시하고 적용/취소 선택

### 5.2 에이전트 콘솔

- SSE로 TraceStep을 순서대로 표시
- 단계에 맞춰 제안 태그와 노드 역할 변경을 지도에 반영
- 성공률, 충돌률, 전달률, 비행 시간, 설치 태그 수 계기판
- 수치가 아닌 3줄 브리핑
- 승인 전 상태 `초안`, 승인 뒤 `사용 가능`, 시나리오 변경 뒤 `stale`

### 5.3 미션 라이브러리

- 실행별 카드: 상태, 카드 ID, 정책, 성공률, 전달률, 시간, 설치 수
- 같은 시나리오의 변형 비교
- 승인된 실행만 패키지 다운로드 허용
- 플랜 카드: tag36h11 ID 500번대, 임무명, 정책, 검증 요약, 인쇄 여백

### 5.4 EMP 드릴

- 온라인 청록색에서 오프라인 호박색으로 명확히 전환
- `LINK LOST`와 API 비활성 표시
- 카나리아 하트비트 정지 → 정숙 확인 → 둥지 개방 → 카드 판독 → 이륙 → 노드 교신 → 귀환 타임라인
- 몬테카를로 궤적 재생, 0.5×/1×/2× 속도, 샘플 선택
- 현재 웨이포인트, 운반 메시지, 노출 시간과 최종 결과 표시

### 5.5 실기기 제어 패널

- Chrome/Edge Web Bluetooth로 XIAO Nordic UART Service를 연결하고 브라우저가 연결을 소유
- 하단 베이에 BLE·FC USB·UART5 링크, ARM, 스로틀, 모터 4개, CH6 제어권, 마스크, 전압을 상시 표시
- 우측 드로어에 연결, FC 상태, 센서, 제어권(보드 송신값 vs FC 적용값), 안전 게이트, 보드 명령, RAM 마스크 시험 카드
- 보드 명령은 `info`, `msp on/off`, `mission reset`, `kill`, `kill off`(2단계 확인)와 접근 제어 `approach`, `approach params`, `approach shadow/off/reset`, `approach set <허용 이름> <범위 안 값>`, `approach on/legacy`(2단계 확인 + 지상 준비 완료 필요)만. 자유 입력 없음
- 접근 제어 카드는 펌웨어 `approach` 보고(모드·상태·고장 사유·거리·목표/실측 속도·롤/피치 명령)를 5Hz로 표시하고, 2초 이상 끊기면 안전으로 해석하지 않음. `max_speed`는 UI에서 10cm/s를 넘길 수 없음
- 보드가 스로틀 슬롯에 1100µs 이상을 보내면(펌웨어 -24 이전) 지상 제어를 잠그고 사유를 표시
- RAM 마스크 7/64/67/71은 확인 문구 + 30초 일회성 토큰의 2단계로만 변경하고 EEPROM에는 쓰지 않음. 7/67/71은 전체 적용 게이트, 64는 복구 게이트를 사용함
- 펌웨어 -25의 50Hz 상시 RC 송신과 FC 적용 제어권을 구분함. `rc_tx:true`만으로 자동 제어라고 표시하지 않고 최신 `authority`를 사용함. 스로틀은 `thr_slot`/`rcmap`으로 판정함
- `authority` 전환 이벤트와 `warn code:vz`를 표시함. 수직 속도 경고는 기록·표시뿐이고 스로틀 명령을 만들지 않음. 마스크 7에는 CH7 킬이 포함되지 않음을 표시함
- BLE 끊김, FC 조회 실패, `fc_link:false`, 아밍 감지 시 즉시 잠금. 킬 버튼만 BLE 연결 중 항상 활성
- `비행 출력 잠금` 사유를 항상 노출하고, 어떤 상태에서도 "비행 가능"을 표시하지 않음
- 연결하지 않아도 나머지 제품은 정상 동작

운용 절차와 게이트 정의는 `docs/HARDWARE_CONTROL.md`를 따른다.

### 5.6 접근 제어 시뮬레이션 (심사 시연용)

- 실기기 없이 AprilTag 저속 접근 알고리즘을 전체 화면으로 시연한다. 하단 베이 `접근 시뮬레이션` 버튼 또는 접근 제어 카드에서 연다
- 제어기는 펌웨어 -25 `approach.h`의 계산(거리 비례 속도 프로파일, 0.10m/s² 가속 제한, 속도 P/I, 슬루·클램프, 마스크 고장 우선순위, 중앙/태그 유실 중립, 과속 제동)을 TypeScript로 옮긴 것이고, 참조 호스트 테스트의 기대 동작과 단위 테스트로 검증한다
- 기체 모델(스틱 1µs = 1cm/s², 자세 지연 0.3s, 항력, 태그·광류 잡음, 카메라 300ms 주기, 55° 시야 반경 \(h\tan 27.5^\circ\))은 가정값이며 화면에 "후보값, 지상 시험에서 확정"으로 명시한다
- 각본 6종: 정상 접근, 태그 상실→제동→복귀, 수동 전환 회수, 광류 신뢰도 저하 중지, 바람 외란 속 도착(속도 PI), 수동→자동 기준점 핸드오버. 각본은 자막으로 설명하고 끝나면 결과 카드(도착 여부·시간·최종 거리·최대 속도·최대 명령·중지/제동 횟수)를 띄운다
- -25 기본값은 `deadband_neutral=1`, `lost_neutral=1`, `overspeed=12cm/s`다. 태그 제동 비교 각본만 `lost_neutral=0`, 바람 PI 비교 각본만 `deadband_neutral=0`을 명시한다. 핸드오버 기준점은 `approach.h` 밖의 동작을 문서에 따라 설명하는 별도 모델이며 실측 검증값으로 표시하지 않는다
- 외란 수동 주입(태그 가리기, CH6 수동/자동, 광류 저하/회복, 옆바람, 킬)과 실행 중 파라미터 슬라이더(최대 속도 ≤10cm/s, 감속 시작, 최대 가속도, 속도 P/I, 롤 부호 반전)로 "부호를 잘못 잡으면 어떻게 되는지"까지 보여 준다
- 화면 전체에 `SIMULATION · 실기기 아님` 플래카드를 상시 노출하고, 시뮬레이션은 어떤 명령도 보드나 FC에 보내지 않는다

## 6. API와 데이터

- `GET/PUT /api/scenarios/{name}`: 시나리오 조회·저장
- `POST /api/validate`: 필드 검증
- `POST /api/analyze`: 전장 분석
- `POST /api/agent/patch`: 자연어 → 시나리오 패치와 diff
- `POST /api/plan/stream`: SSE 계획 실행
- `GET /api/library`: 실행 목록
- `POST /api/runs/{id}/approve`: 사람 승인 게이트
- `GET /api/runs/{id}/package`: 승인 패키지
- `GET /api/cards/{id}.png`: 플랜 카드
- `GET /api/drill/{id}`: 오프라인 재생 타임라인
- `GET /api/hardware/profile`: 실기기 토폴로지(식별자 제외)
- `GET /api/hardware/fc/status`: FC 식별·무장·RC·모터·모드·마스크·안전 게이트
- `POST /api/hardware/fc/override/challenge`, `POST /api/hardware/fc/override/apply`: `msp_override_channels` 7/64/67/71 RAM 변경 2단계

모든 실행은 `artifacts/{run_id}/`에 저장한다. `metadata.json`이 입력 해시, 상태, 카드 ID, 생성 시각을 기록하며 `artifacts/README.md`가 현재 목록을 설명한다.

## 7. LLM 정책

- 공급자: OpenAI, AWS Bedrock, none
- 모델 응답은 JSON 패치 또는 텍스트 브리핑으로 제한한다.
- 플래너 trace에 없는 수치를 생성하지 않는다.
- 키 없음, 시간 초과, 스키마 오류 시 none 공급자로 자동 폴백한다.
- 적용 전 diff와 사용자 승인이 필수다.

## 8. 안전과 접근성

- Failsafe DROP, 수신기 미연결, 가정 기반 드리프트·링크 모델 경고를 화면에 상시 노출
- 색만으로 상태를 전달하지 않고 텍스트·아이콘을 병행
- 키보드 포커스, 충분한 대비, `prefers-reduced-motion` 지원
- 앱은 아밍, 스로틀, 모터 시험, 원시 MSP 명령을 제공하지 않는다. FC 쓰기는 `msp_override_channels` 7/64/67/71 RAM 변경 한 가지뿐이다.
- 실기기 제어는 프로펠러 제거·디스아밍 상태의 지상 채널 시험까지만 허용하며, 비행 출력 잠금 사유가 모두 해소돼도 UI가 비행을 허가하지 않는다.

## 9. 성공 기준

- 기존 138개 테스트와 신규 API 테스트가 통과한다.
- `demo_spider` 계획이 UI에서 실행되어 제안 태그와 BLE→광학 전환이 보인다.
- SSE가 `complete` 또는 `error` 이벤트로 종료된다.
- 승인 전 패키지 요청은 거부되고 승인 뒤 ZIP이 내려온다.
- 생성 카드가 유효한 PNG이며 지정 tag ID를 포함한다.
- LLM 키 없이 자연어 폴백, 계획, 승인, 드릴이 모두 동작한다.
- 1440×900 화면에서 주요 데모 흐름이 스크롤 최소화로 진행된다.

## 10. 2분 데모

1. `demo_spider`를 열고 “노드 3을 대피소로, 사진 30KB 회수 메시지 추가”를 입력한다. 노드 호출명과 사진 메시지 두 항목의 diff를 확인한다.
2. diff를 적용하고 에이전트를 실행한다.
3. 전달률 미달과 노드 2의 광학 전환, 최종 100%를 확인한다.
4. 임무를 승인하고 플랜 카드와 C 헤더를 확인한다.
5. EMP 드릴을 재생해 링크 두절부터 귀환까지 보여 준다.
6. `접근 시뮬레이션`을 열어 "태그 상실 → 제동 → 복귀" 각본(`lost_neutral=0` 비교)을 2×로 재생하고, 결과 카드에서 10cm/s 상한 안에서 5cm 이내 도착을 확인한다. 기본 태그 유실 동작은 중립 수렴임을 함께 설명한다. 실기기가 있으면 접근 제어 카드의 shadow 보고가 같은 수치 체계로 들어오는 것을 보여 준다.
