한국어 데모 흐름을 로컬 환경에서 확인했다. 실제 기체 동작이나 비행 성능을 검증한 기록은 아니다.

이 기록은 -25 인수 작업의 검증이다. 이어서 수행한 3D·UI/UX 개편 및 웹 테스트 99개 결과는 [UI/UX 개편 기록](UI_UX_REFRESH.md)에 별도로 남겼다.

   기존 코드에서 실패하는 것을 확인한 뒤 파싱·판정·표시를 수정했다.
2. **마스크 7/71**: 기존 코드가 새 대상을 거부하는 실패를 확인한 뒤 API·writer·웹을 수정했다.
   허용값은 7/64/67/71뿐이다. 7/67/71의 전체 적용 게이트, 64의 복구 게이트, 정확한 확인 문구,
   쓰기 활성 플래그, 30초 만료·일회성·대상 결합 토큰, 적용 직전 재조회, 되읽기 및 EEPROM 쓰기 부재를 검증했다.

추가 회귀 검증은 송신 직전 현재 시각으로 MSP/접근/FC 신선도를 다시 확인하는 것, `rc_tx` 누락과 잘못된
매핑의 차단, FC 조회 오류 시 즉시 잠금, 기존 `can_apply_67` 호환 필드를 포함한다.

### 펌웨어 참조와 시뮬레이터

- 제어기 기준은 `hardware/reference/firmware-25/approach.h`와 `approach_host_test.cpp`다.
  고장 우선순위, 중앙·태그 유실 중립 정책, 과속 제동, 가속·명령 변화율·클램프, 도착 유지 조건을 비교했다.
- 기존 문서의 “호스트 테스트 13종”과 달리 복사된 C++ 파일의 `main()`은 **12개 테스트 함수**를 호출한다.
  이번 환경에는 C++ 컴파일러가 없어 **C++ 호스트 테스트 바이너리는 빌드하거나 실행하지 않았다**.
  복사본의 기대 동작을 읽고 TypeScript 회귀 테스트로 대응 동작을 검증했다.
- 시뮬레이터 기본값은 `deadbandNeutral=1`, `lostNeutral=1`, `overspeedCmS=12`다.
  태그 상실·복귀 각본만 `lostNeutral=0`, 바람 각본만 `deadbandNeutral=0`과 속도 I 게인을 쓰는 비교다.
- 수동→자동 기준점 모델은 문서에 근거한 시각화다. `approach.h`의 제어기 계산과 분리되어 있으며,
  실제 보드 50Hz 송신 시점과 FC 지연을 검증하지 않는다. 시뮬레이션 수치적분은 20Hz다.

다음은 자동테스트에서 확인한 조건이다. 브라우저에서 확인한 각본 결과는 3절에 별도로 적었다.

| 항목 | 통과한 자동테스트 조건 |
|------|-------------------------|
| 정상 접근 | 도착, 최종 거리 ≤5cm, 고장 0회, 명령 상한 준수. 기체 모델 최대 속도 검증 허용치는 ≤11.5cm/s |
| 태그 상실 비교 각본 | `HOLD` 진입, 마지막 HOLD 목표 속도 약 0, 모델 속도 <2cm/s, 복귀 뒤 도착 |
| 기준점 연결 | AUTO 진입 직전 `[1520,1485,1510]`µs가 첫 AUTO에도 유지됨 |
| 기준점 복귀 | 기본 100µs/s에서 0.05초 뒤 `[1515,1490,1505]`µs, 이후 `[1500,1500,1500]`µs에 수렴 |
| 핸드오버 각본 | 표시용 10µs/s에서 3.5초 시점까지 기준점이 1500으로 복귀; AUTO 중 추가 조종기 움직임을 다시 기준점으로 채택하지 않음 |
| 수동 회수·광류 저하 | 수동에서 명령 0 및 `manual_authority`, 품질 저하에서 `FAULT/flow`, 회복 뒤 도착 |

`max_speed=10cm/s`는 **접근 목표 속도 상한**이다. 기체 모델의 관성·외란 때문에 모델 실제 속도가 10을
넘을 수 있다. UI는 이를 경고하고 그래프 축을 실제 값에 맞춰 늘리며, 시뮬레이터가 실제 속도 10 이하를
보장하는 것처럼 표시하지 않는다.

## 3. 브라우저 데모 확인

LLM 없이(`D4D_LLM_PROVIDER=none`) 로컬 API와 Vite를 사용했고 브라우저 화면은 1440×900이었다.

| 흐름 | 확인 결과 |
|------|-----------|
| 자연어 수정 | “노드 3을 대피소로, 사진 30KB 회수 메시지 추가”가 대피소 호출명 변경과 사진 회수 메시지의 두 diff로 표시됨 |
| 계획 실행 | 전달률 86%에서 수정 후 최종 100%로 진행되는 결과 확인 |
| 승인 게이트 | 승인 전 카드·패키지 잠금, 승인 후 다운로드 가능 |
| 패키지 | 승인 실행의 ZIP 항목 9개 확인. 플랜 카드 PNG와 C 헤더 확인 |
| 원본 시나리오 | 원본 ID로 계획 후 승인 시 발생하던 HTTP 409를 재현·수정하고 다시 검증 |
| EMP 드릴 | 마지막 착륙까지 진행되고 자동 정지 후 완료 상태 유지 |
| 카드 한국어 | 일반 제목과 긴 한국어 제목 카드 재생성 후 이미지로 글자·줄바꿈 확인 |
| 태그 상실·복귀 각본 | 성공, 도착 17.3초, 최종 거리 1.1cm, 최대 모델 속도 9.7cm/s, 고장/태그 상실 0/1 |
| 수동→AUTO 핸드오버 각본 | 성공, 도착 9.2초, 최종 거리 2.7cm, 최대 모델 속도 21.5cm/s와 10 초과 경고, 최종 기준점 1500/1500/1500µs, 고장/태그 상실 1/0 |
| 미연결 하드웨어 패널 | 연결 없는 상태에서 게이트 6개 차단과 모든 명령 잠금 확인 |

최종 원본 시나리오 실행 ID는 `30b3a04543dd44f4a38f0e50f06d996f`다. 작업공간의
`work/demo-proof/final-verification.json`에는 한글 카드 PNG 31,505바이트, ZIP 항목 9개,
드릴 이벤트 31개와 마지막 착륙 이벤트 `T=230.0초`를 기록했다. 이 경로는 checkout 밖 로컬 검증
산출물 경로다. 앞선 `verification.json`의 실행 `10c7179a21c441fc99db6aa725496b02`와
카드 13,114바이트는 한글 수정 전 증거이므로 최종 카드와 구분한다.

핸드오버 각본의 21.5cm/s는 관성·기준점 이동을 포함한 **기체 모델 속도**다. UI의 10cm/s 초과 경고와
함께 확인했으며, 이를 10cm/s 이내 제어 성능의 증거로 해석하지 않는다. 같은 각본의 고장 1회는
수동 제어권 구간의 `manual_authority`를 포함한다.

이 표는 기능별 리허설 결과다. 실제 EMP, 실제 비행, 연결된 보드 동작, 2분 연속 시연 시간을 검증하지 않았다.

### 리허설 중 수정한 문제

- React effect가 Promise를 반환해 초기 화면을 깨뜨리던 문제를 정리했다.
- 원본 시나리오의 float가 JavaScript에서 재직렬화되어 승인 해시가 달라지던 문제를 수정했다.
  변경되지 않은 원본은 ID로 요청하며, 실제 수정안은 내용을 보낸다. 서버의 승인 해시 검증은 유지했다.
- 결정론적 자연어 수정에서 대피소 호출명이 누락되던 부분과 패치 취소 흐름을 보완했다.
- 시뮬레이터의 반복 포커스 이동을 막고 Space 조작을 정리했다.
- 드릴이 착륙 완료 뒤에도 재생 상태를 유지하던 문제를 수정했다.
- 카드가 Pillow 기본 글꼴로 한글을 네모로 그리던 문제를 수정했다. Windows 맑은 고딕과 Linux
  Noto CJK/Nanum 등 설치된 글꼴을 선택한다. 글꼴이 없으면 오류로 알리며 자동 설치·다운로드하지 않는다.
  제목과 안내문은 태그 왼쪽 영역에 맞춰 표시하고, 기존 태그 영역 픽셀은 그대로임을 비교했다.
- 실제 모델 속도 10cm/s 초과 경고와 그래프의 동적 범위를 추가했다.
- 미연결·오래된 FC/보드 보고를 차단 사유 “없음”, 킬 “해제”로 표시하지 않고 “미확인”으로 표시한다.
  이 마지막 표시 수정 후 hardware 51개 테스트와 빌드를 다시 통과했고, 최종 브라우저에서 확인했다.

## 4. 안전 경계와 남은 확인

- 검증 과정에서 실제 기체·BLE·FC에 연결하지 않았다. 하드웨어 쓰기는 `D4D_HARDWARE_WRITES=0`,
  FC 포트는 `SIMULATION_NO_DEVICE`로 설정했다. API 쓰기 테스트는 가짜 FC 객체로 수행했다.
- 아밍·스로틀·모터 시험·원시 MSP·자유 입력 명령을 추가하지 않았다. FC 쓰기 경로는 여전히
  `msp_override_channels` RAM 변경 한 가지이며 EEPROM 저장은 없다.
- 마스크 7에는 CH7이 없어 보드 킬을 FC로 전달하지 못한다. 71을 포함한 어떤 허용 마스크에서도
  킬 버튼 표시만으로 FC 정지·디스아밍을 보장하지 않는다.
- 실제 펌웨어 업로드, -25 송신율·제어권 전환 지연·스로틀 소유권·축과 부호·킬 반응 검증은 남아 있다.
  보관된 텔레메트리 샘플과 합성 테스트 이벤트를 새 실측 기록으로 취급하지 않는다.
- Git push, 원격 배포, 호스팅·계정·비용 설정은 수행하지 않았다.

실기기 운용 조건은 `docs/HARDWARE_CONTROL.md`, 변경 요약과 후속 작업은 `docs/HANDOFF_CODEX.md`를 따른다.
