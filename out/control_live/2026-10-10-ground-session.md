# 2026-10-10 지상 세션 기록 (읽기 전용 증거)

프로펠러 제거, 기체 고정 상태. 조종은 BLE(`tools/tag_monitor.py --ble`)와 FC USB(COM9)로 수행.
세션 종료 시각 약 14:50, 이후 케이블을 분리해 엔지니어에게 인계.

## 구성

| 항목 | 값 |
|------|-----|
| FC | MicoAir H743 V2, INAV 9.1.0, 4S 13.59V |
| 보드 | XIAO ESP32S3 Sense, `TagBoard-B8B4`, 빌드 `TAGVISION-20261010-22` (이날 업로드) |
| 보드↔FC | UART5 MSP, `fc_link:true`, 응답률 ≥ 99.9%, 오류 0 |
| 높이 | `height_src:"fc"` (MTF-01P → FC UART4 → 보드) 2~4cm 정지 상태값 |
| 카메라 | OV2640 640×480, 2.6~4.6fps, 세션 중 등록 태그 미검출(`NO_TARGET`) |

## 1. RAM 마스크

- `msp_override_channels` **64 → 67** RAM 적용·되읽기 성공(Python `d4d_fc.control_write`, EEPROM 미저장).
- **64 복구는 수행하지 않은 채 케이블 분리.** FC 전원 재인가 시 영구값 64로 돌아간다.
  다음 연결 때 `GET /api/hardware/fc/status`의 `mask`가 64인지 먼저 확인할 것.

## 2. 제어권 전환 (CH6) — 통과

| 단계 | 조종기 | 보드 텔레메트리 | FC |
|------|--------|-----------------|----|
| 자동 | CH6=1000 | `authority:auto`, `authority_fresh:true`, `rc_tx:true`, `sent` 증가 | `fc_rc` 롤/피치 1500/1500 = 보드 `out` |
| 수동 전환 | CH6=2000 | `authority:manual`, `rc_tx:false`, `sent` 고정(1043) | 디스암, 모터 1000 |
| 수동 우선 | CH6=2000 + 롤 스틱 우측 끝 | `rc_tx:false` | `fc_rc[0]=2000` (조종기 입력 그대로) |
| 자동 복귀 | CH6=1000, 스틱 중앙 | `authority:auto`, `rc_tx:true`, `sent` 1393→1410 증가 | 롤/피치 1500/1500, 모터 1000 |

결론: 보드 자동 송신 중 CH6=2000이면 즉시 송신을 멈추고 조종기가 우선한다. 복귀도 정상.

## 3. 자동 경로 중립 반영 — 부분 통과

- CH6=1000에서 보드 `out` 1500/1500 → FC `fc_rc` 1500/1500 일치.
- 태그가 보이지 않아 **비중립 롤·피치 반영은 미검증**.

## 4. 모터 지상 구동 (`motortest`, MSP_SET_MOTOR 직접 구동)

| 시각 | 명령 | 결과 |
|------|------|------|
| 14:44 | `motortest all 10 5` | FC `motor:[1100,1100,1100,1100]` 확인. 약 2초 뒤 CH6=2000으로 전환되자 `stopping reason:manual_authority` → 1000 복귀 |
| 14:50 | 20회 반복(5초 구동/5초 정지, 매회 사전 조건 재검사) | 1회차 정상 완료(`fc_acks:108`). 2회차 시작 직후 CH6 수동 전환 감지 → 전체 중단, `motorstop` 송신, 모터 1000 확인 |

차단 동작 확인: 사용자가 CH6을 올리는 것만으로 보드가 모터 시험을 즉시 중단했다.

주의 기록: 세션 초반 사용자가 조종기로 아밍한 상태에서 모터 출력 최대 1695µs가 관측됐다(보드 명령 아님).
CH5=2000이면 보드는 모터 시험을 거부하며, 이 상태는 조종기 책임 영역이다.

## 5. 거부된 요청

- "멈추라고 할 때까지 10%로 5초씩 계속": 무기한 반복은 펌웨어 5초 상한 우회·과열 위험으로 거부. 20회 상한으로 대체.
- 스로틀 1105µs 상태에서 시작 요청: 안전 한계 1100 초과로 대기 후 1000 확인 뒤 진행.
